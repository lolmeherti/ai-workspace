### Mechanism of Prompt Injection in LLMs

**Core Vulnerability: Lack of Instruction-Data Separation**
The fundamental mechanism behind prompt injection is the architectural inability of LLMs to distinguish between **instructions** (system commands) and **data** (user input). 
*   **Traditional Software:** Uses clearly defined syntax to separate executable code from input data.
*   **LLMs:** Process everything as natural language text. Because instructions and data are processed within the same linguistic stream, the model cannot inherently determine if a piece of text is a command to be followed or information to be processed.

**Primary Attack Vectors**
*   **Direct Prompt Injection:** An attacker provides input directly to the model designed to override its original system instructions and alter its behavior.
*   **Indirect Prompt Injection:** The model processes untrusted external content (such as a website, an email, or a document) that contains hidden instructions. This allows the model's behavior to be manipulated without the user's direct involvement or awareness.
*   **RAG (Retrieval-Augmented Generation) Poisoning:** Attackers insert malicious instructions into documents that are later retrieved by the LLM to provide context, which can manipulate the model's responses with high efficacy.

**Key Distinctions and Concepts**
*   **Prompt Injection vs. Jailbreaking:** 
    *   **Prompt Injection** focuses on manipulating the **functional behavior** of the model (e.g., making it execute unauthorized code or leak data).
    *   **Jailbreaking** specifically targets **safety mechanisms** to bypass content filters and ethical guardrails.
*   **Confused Deputy Attack:** This occurs when an AI agent, acting on behalf of a user, is tricked into using its authorized tools (like sending emails or modifying databases) to perform unauthorized actions because it was "convinced" by malicious tokens found in untrusted input.
