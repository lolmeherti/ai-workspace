Prompt injection in Large Language Models (LLMs) is a vulnerability stemming from the model's architectural inability to distinguish between **instructions** (system commands) and **data** (user input).

### How Prompt Injection Works
The mechanism behind this vulnerability lies in how LLMs process information. Unlike traditional software, which uses clearly defined syntax to separate executable code from input data, LLMs process everything as a single stream of natural language text. Because instructions and data exist within the same linguistic stream, the model cannot inherently determine whether a piece of text is a command it should follow or merely information it should process.

### Primary Attack Vectors
There are three main ways an attacker can execute a prompt injection:

*   **Direct Prompt Injection:** An attacker provides input directly to the model designed to override its original system instructions and change its behavior.
*   **Indirect Prompt Injection:** The model processes untrusted external content—such as an email, a website, or a document—that contains hidden instructions. This allows the model to be manipulated without the user's direct involvement.
*   **RAG (Retrieval-Augmented Generation) Poisoning:** Attackers insert malicious instructions into documents. When the LLM retrieves these documents to provide context for a response, the malicious instructions can manipulate the model's output with high efficacy.

### Key Concepts and Distinctions
To understand prompt injection fully, it is important to distinguish it from other concepts:

*   **Prompt Injection vs. Jailbreaking:** While they are related, they have different goals. **Prompt injection** focuses on manipulating the **functional behavior** of the model (such as leaking data or executing unauthorized code). **Jailbreaking** specifically targets **safety mechanisms** to bypass ethical guardrails and content filters.
*   **Confused Deputy Attack:** This is a specific consequence of prompt injection where an AI agent is tricked into using its authorized tools—such as modifying databases or sending emails—to perform unauthorized actions because it was "convinced" by malicious tokens found in untrusted input.
