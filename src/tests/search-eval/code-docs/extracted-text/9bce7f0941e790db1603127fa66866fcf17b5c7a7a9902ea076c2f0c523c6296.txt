In Go&rsquo;s net/http package, middleware provides an elegant mechanism to add cross-cutting concerns such as logging, authentication, content validation, and header manipulation without cluttering your handler logic.While many Go web frameworks offer middleware systems, Go&rsquo;s standard library provides all the tools necessary to build powerful, production-ready middleware components. This article demonstrates how to develop custom middleware in Go using only the standard library, giving you complete control over your application&rsquo;s request processing pipeline without external dependencies.What is Middleware?Middleware is a function that wraps an HTTP handler, allowing you to execute code before and after the handler processes a request. Think of middleware as a series of concentric layers surrounding your core business logic &mdash; each layer can inspect, modify, or even halt the request before it reaches the handler, and similarly process the response on its way back to the client.The middleware pattern in Go follows a simple signature:This function takes an http.Handler as input and returns a new http.Handler that wraps the original. This design enables elegant composition where multiple middleware components can be chained together, each adding its own functionality to the request processing pipeline.Key characteristics of middleware:Execution order: Middleware executes in the order it&rsquo;s wrapped, with the outermost middleware executing first on the way in and last on the way out.Request/response access: Each middleware has full access to both the request and response, allowing for inspection, modification, or early termination.Composability: Multiple middleware functions can be composed together, creating a flexible processing pipeline.Developing Middleware in GoLet&rsquo;s examine a practical implementation that demonstrates how to build and compose middleware components using only Go&rsquo;s standard library.The Middleware PatternOur example implements three distinct middleware components, each serving a different purpose:StatisticMiddleware: Global Request TrackingThis middleware serves as a global wrapper for all requests. It logs incoming requests, adds a custom header to the response, and then delegates to the next handler in the chain. The logging statements before and after next.ServeHTTP() demonstrate how middleware can execute code both before and after the actual handler processes the request.2. ContentTypeMiddleware: Request ValidationThis middleware demonstrates request validation and early termination. If the Content-Type header doesn&rsquo;t match the expected value, the middleware returns an error response immediately without calling next.ServeHTTP(). Validation middleware should typically run before business logic middleware. In our example, ContentTypeMiddleware runs before ApiMiddleware, ensuring that invalid requests are rejected before any API-specific processing occurs.Early termination: Middleware can stop the request chain at any point by not calling next.ServeHTTP(). This is useful for authentication checks, rate limiting, or request validation.Response modification: Headers must be added before calling next.ServeHTTP() or before any data is written to the response. Once the response body is written, headers are sent and cannot be modified.ConclusionGo&rsquo;s standard library provides a powerful, elegant foundation for building middleware without requiring third-party frameworks. The http.Handler interface and the ability to wrap handlers through closures create a flexible system that scales from simple logging to complex authentication pipelines.The middleware pattern demonstrated here offers several advantages: complete control over the request/response lifecycle, zero external dependencies, excellent performance, and the ability to compose functionality in a clean, maintainable way.
