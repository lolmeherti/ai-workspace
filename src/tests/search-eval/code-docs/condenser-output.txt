### Go HTTP Middleware (`net/http` Standard Library)

**Definition**
Middleware is a function that wraps an `http.Handler`. It allows for modular, reusable processing of HTTP requests and responses, handling "cross-cutting concerns" like logging, authentication, and validation without cluttering core business logic.

**The Core Interfaces**
* **`http.Handler`**: The fundamental interface. Any type implementing `ServeHTTP(ResponseWriter, *Request)` is a handler.
* **`http.HandlerFunc`**: An adapter type that allows plain functions to satisfy the `http.Handler` interface.
* **Middleware Signature**: `type Middleware func(http.Handler) http.Handler`

**The Middleware Pattern**
Middleware uses **closures** to capture the `next` handler. The function returns an `http.HandlerFunc` which, when executed, runs the middleware logic and then calls `next.ServeHTTP()`.

```go
func exampleMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // 1. Logic executed on the way "in" (Request phase)
        next.ServeHTTP(w, r) 
        // 2. Logic executed on the way "out" (Response phase)
    })
}
```

### Advanced Implementation Patterns

#### 1. Middleware Chaining (The `Chain` Function)
Manually nesting middleware (`A(B(C(handler)))`) becomes unreadable as complexity grows. A `Chain` function can take a slice of middleware and apply them in order.
* **Crucial Logic:** To ensure the first middleware in the slice is the **outermost** (the first to receive the request), the chain must iterate through the slice in **reverse order**.

```go
func Chain(middlewares ...Middleware) Middleware {
    return func(final http.Handler) http.Handler {
        for i := len(middlewares) - 1; i >= 0; i-- {
            final = middlewares[i](final)
        }
        return final
    }
}
```

#### 2. Capturing Response Data (The Wrapper Pattern)
The standard `http.ResponseWriter` does not expose the status code once it has been written. To log status codes, you must create a custom struct that embeds `http.ResponseWriter` and intercepts the `WriteHeader` call.

```go
type responseWriter struct {
    http.ResponseWriter
    status int
    written bool
}

func (rw *responseWriter) WriteHeader(code int) {
    if !rw.written {
        rw.status = code
        rw.written = true
        rw.ResponseWriter.WriteHeader(code)
    }
}
```

#### 3. Configurable Middleware (The Factory Pattern)
When middleware requires configuration (e.g., a timeout duration), use the **Factory Pattern**: a function that accepts configuration and returns the actual `Middleware` function.

```go
func TimeoutMiddleware(timeout time.Duration) Middleware {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            // Implementation using context.WithTimeout...
        })
    }
}
```

#### 4. Context Management & Safety
Middleware often passes data (like User IDs) downstream using `context.WithValue`.
* **Avoid Collisions:** Never use plain strings as context keys. Use a **private, custom type** to ensure no other package can overwrite your data.
* **Short-circuiting:** If authentication fails, call `http.Error` and **must return immediately** to prevent the execution of the `next` handler.

```go
type contextKey string
const UserIDKey contextKey = "userID"
```

### Common Middleware Types & Best Practices

| Type | Key Implementation Detail | Placement in Chain |
| :--- | :--- | :--- |
| **Panic Recovery** | Uses `defer` and `recover()`. Use `runtime/debug.Stack()` for logs. | **Outermost** (to catch everything). |
| **Logging** | Wraps `ResponseWriter` to capture status/duration. | Near the top. |
| **Timeout** | Uses `context.WithTimeout` and a `select` statement. | Before heavy logic. |
| **Authentication** | Validates tokens and injects data into `r.Context()`. | After logging/recovery. |

**Key Mechanics Recap**
* **Execution Order:** Middleware executes in the order it is wrapped. The outermost middleware executes first on the "in" phase and last on the "out" phase.
* **Early Termination:** A middleware can halt the chain by simply **not** calling `next.ServeHTTP()`.
* **Response Modification:** Headers must be added *before* calling `next.ServeHTTP()` or writing the body.

**Execution Flow Example**
`Recovery` $\rightarrow$ `Logging` $\rightarrow$ `Auth` $\rightarrow$ `Handler`
1. **Request In:** `Recovery` $\rightarrow$ `Logging` $\rightarrow$ `Auth` $\rightarrow$ `Handler`
2. **Response Out:** `Handler` $\rightarrow$ `Auth` $\rightarrow$ `Logging` $\rightarrow$ `Recovery`

### When to Use a Framework (e.g., Chi, Gin)
While `net/http` is powerful, frameworks are preferred when you need:
* **Complex Routing:** Regex, optional segments, or advanced path parameters (though Go 1.22 improved standard library wildcards).
* **Route Grouping:** Applying specific middleware to a subset of routes (e.g., `/api/*`) more cleanly than manual mux setup.
